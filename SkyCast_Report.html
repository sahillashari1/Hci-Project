1. Introduction

SkyCast is a modern weather dashboard built as an individual semester project for the Human-Computer Interaction (HCI) course. It presents current weather, hourly forecasts, a seven-day outlook, a simulated weather map with insights, and a settings page. The application is built with HTML, CSS and JavaScript in a single file (index.html) and runs locally in a web browser without installation, an internet connection or an API key. The focus of the project is the application of HCI design principles to create an interface that is clear, consistent, responsive and pleasant to use.

2. Problem Statement

Many weather applications are cluttered with advertisements, hide important information behind several menus, or use inconsistent layouts. Users who simply want to know "what is the weather now and what will it be later?" must often search through confusing screens. There is a need for a weather interface that shows the most important information at a glance, gives clear feedback, and lets users stay in control of units, theme and location.

3. Project Objectives

  • Design and develop a clean, modern and responsive weather dashboard.
  • Apply at least five HCI principles visibly in the interface.
  • Provide five connected screens: Home, Hourly, 7-Day, Weather Insights/Map and Settings.
  • Allow users to search and switch cities, change units (°C/°F) and change theme (dark/light).
  • Give immediate visual feedback for every user action.
  • Work offline using simulated sample data.

4. Project Scope

The project covers the design and front-end implementation of the interface. It includes six sample cities (Karachi, Lahore, Islamabad, Dubai, London and New York), simulated hourly and daily forecasts, interactive charts, a simulated radar visualization and user preferences saved in the browser. It does not include a back-end server, a real weather API, user accounts or real push notifications.

6. Design Methodology

A user-centred design approach was followed in four stages:

  1. Requirement analysis: identifying what information users need most (temperature, condition, rain, wind, forecast).
  2. Design: planning the layout (sidebar navigation, card-based content), colour palette (dark navy, sky blue, white, purple accent) and glassmorphism card style.
  3. Implementation: building the interface with HTML, CSS and JavaScript, using inline SVG icons and charts.
  4. Evaluation: testing each feature against a test table and checking the interface against HCI heuristics.

7. System Features

  • Five fully working screens with active-state navigation.
  • City search with suggestions, quick city chips and error messages for unknown cities.
  • Live local clock and date for the selected city.
  • Current temperature, condition, high/low, feels-like, humidity, wind, UV index, visibility, sunrise and sunset.
  • 24-hour forecast cards and smooth SVG temperature charts.
  • 7-day forecast with visual temperature range bars, rain probability and wind.
  • Simulated animated weather radar with rain, cloud and temperature layers.
  • Celsius/Fahrenheit conversion (also converts wind speed and visibility).
  • Dark/light theme, notification preferences, default city, settings reset.
  • Responsive layout for desktop, tablet and mobile.

9. HCI Principles Implemented

PrincipleHow it is implemented in SkyCast
1. Visibility of System StatusThe current temperature, condition and forecasts are always visible. A status badge in the top bar shows "Demo data · city · updated time". When a city is changed, a loading bar appears, the status dot turns amber and the content dims until the new data is displayed. The active navigation item is highlighted, and the live clock shows that the app is running.
2. ConsistencyThe same font, colour palette, rounded glass cards, icon style, button style and spacing are used on all five screens. Navigation is always in the same place (sidebar on desktop, bottom bar on mobile). Temperatures and units are formatted the same way everywhere.
3. Recognition Rather Than RecallEvery navigation button has both an icon and a text label. Weather conditions are shown with recognisable icons (sun, cloud, rain) and emoji labels (💧 rain, 🌬️ wind). City chips and a search suggestion list mean users never need to remember city names. UV levels use words and colours (Low, High) instead of only numbers.
4. User Control and FreedomUsers can switch cities at any time, change °C/°F from the top bar or Settings, toggle dark/light theme, move freely between screens, choose a default city and reset all settings with one button. Nothing is forced or permanent.
5. FeedbackEvery action gives a response: toast messages appear after searching ("Showing weather for Dubai"), changing units, toggling theme or notifications, and changing radar layers. Unknown cities show a clear error message. Buttons and cards have hover and press effects; switches slide to show on/off state.

Additional principles: Error prevention and helpful error messages (empty or unknown search), aesthetic and minimalist design (information grouped into cards), accessibility (labels, keyboard focus outlines, "/" shortcut to focus search, reduced-motion support) and flexibility and efficiency of use (quick unit/theme buttons).

10. User Interface Design

  • Colour scheme: dark navy gradient background with sky-blue and purple accents and white text, giving high contrast and a premium look. A light theme is also available.
  • Glassmorphism: semi-transparent cards with background blur, thin borders and soft shadows.
  • Typography: Segoe UI / system sans-serif fonts; large bold temperature, smaller muted labels for hierarchy.
  • Icons and illustrations: custom inline SVG weather icons with day and night versions.
  • Layout: CSS Grid and Flexbox; sidebar navigation on desktop becomes a bottom navigation bar on mobile.
  • Motion: screen fade-in, floating hero icon, hover lift on cards, loading bar and toast animations.

11. Usability Features

  • Information is grouped into cards so the most important data is seen at a glance.
  • Responsive design works on phones, tablets and desktops.
  • Search accepts partial names (for example "dub" finds Dubai).
  • User preferences (unit, theme, notifications, default city) are saved in the browser's localStorage.
  • Works fully offline with no installation.
  • Honest labelling of simulated data on the status bar, map screen and settings page.

14. Limitations

  • All weather information is simulated demo data. It is generated by formulas and sample values stored in the code. It is not live data and is not obtained from any real weather API or weather service.
  • The application does not use a real weather API, so it cannot show real current conditions, real forecasts or real warnings.
  • The weather map/radar is a schematic simulation, not a real geographic or satellite radar.
  • Only six cities are available.
  • Notification settings are saved but no real notifications are sent.
  • No user accounts or database; preferences are stored only in the local browser.
  • No formal usability testing with a large group of real users was performed.

15. Conclusion

SkyCast demonstrates how HCI principles can be applied to build a clear, attractive and easy-to-use weather interface. The application provides five working screens, interactive controls, helpful feedback and a responsive design using only HTML, CSS and JavaScript. Although it uses simulated data instead of a real weather API, the interface and structure are designed so that a real API could be connected in the future. The project helped to understand the importance of user-centred design, consistency, feedback and user control in software interfaces.

Future Work

  • Connect a real weather API (for example Open-Meteo) for live data.
  • Use GPS location and more cities.
  • Real weather maps and push notifications.
  • User accounts, multiple languages and formal usability testing.

EXTRA 2 – Viva / Presentation Script (not part of the report)

What is SkyCast?

"Good morning, sir/madam. My project is SkyCast, a smart weather dashboard. It shows the current weather, hourly forecast, seven-day forecast, a weather map and settings. It runs in the browser and is built with HTML, CSS and JavaScript."

Why did I choose this project?

"Everyone uses a weather app, so it is easy to understand and a good example for testing HCI ideas. It also lets me practise layout, colours, icons, feedback and user control."

What problem does it solve?

"Many weather apps are crowded and confusing. SkyCast shows the most important information clearly on one screen, so users can understand the weather quickly."

How did I design the interface?

"I used a dark blue gradient with sky-blue and purple colours, and glass-style cards with rounded corners. There is a sidebar for navigation, which becomes a bottom bar on mobile phones. I used big text for temperature and smaller text for details so the user sees the important data first."

Which HCI principles did I implement?

  1. Visibility of system status: the status bar, loading bar and highlighted menu tell the user what is happening.
  2. Consistency: same colours, fonts, cards and icons on every screen.
  3. Recognition rather than recall: icons with labels and city buttons, so the user does not have to remember anything.
  4. User control and freedom: the user can change city, units and theme, and reset the settings at any time.
  5. Feedback: pop-up messages and animations appear after every action, such as searching or changing units.

Which technologies did I use?

"HTML for structure, CSS for design and responsiveness, JavaScript for logic and interaction, SVG for icons and charts, and the canvas element for the radar animation."

Difference between simulated and real weather data?

"Real weather data comes from satellites, sensors and weather services through an API, and it changes every minute. My data is simulated: I wrote sample values and formulas in the code to make realistic-looking numbers. So the interface is real, but the weather numbers are demo data. I have written this clearly in the app and in the report. The radar is also a simulation."

What can I add in the future?

"A real weather API such as Open-Meteo, GPS location, more cities, real weather maps, real notifications, user accounts, more languages, and testing with real users."

Possible teacher questions

  • How does the °C/°F toggle work? All data is stored in Celsius. When displaying, JavaScript converts with F = C × 9/5 + 32 and re-renders every screen.
  • How are settings saved? In the browser's localStorage.
  • How does search work? It compares the typed text with city names (exact, starts-with, then contains); if found it changes the city, otherwise it shows an error message.
  • How is it responsive? CSS Grid/Flexbox and media queries.
